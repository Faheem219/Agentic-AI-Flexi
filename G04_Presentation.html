Methodology · Stage 3

Control design: identity at every hop

  • P1 One identity per agent, with a named human owner.
  • P2 Authority only narrows along the delegation chain.
  • P3 One gateway checks every tool call (complete mediation).
  • P4 Every decision goes into a tamper-evident log.
  • P5 IDS rules keyed on identity and grant, not IP or key.

Why identity? Model-side classifiers belong to the AI provider, and network IDS sees encrypted calls to legitimate APIs. Identity is the one signal the defending organisation can enforce and log itself.

Implementation · 1 of 2

Tokens, gateway and audit log

Scoped delegation token

JSON claims signed with HMAC-SHA256: grant, chain (human → agents), scopes, resources, expiry, depth, purpose.

delegate() only narrows

Child scope ⊆ parent · resources ⊆ parent · expiry ≤ parent · depth − 1. Otherwise refused: scope_widening, resource_widening, depth_exceeded — and the refusal is logged.

Tool gateway + audit log

One enforcement point checks signature, expiry, scope and resource for every call. Each log record carries the SHA-256 of the previous one.

Python 3 standard library (hmac, hashlib, json, secrets) + matplotlib, about 500 lines. Tool names are abstract labels — the prototype only decides, records and analyses; nothing is executed.
Implementation · 2 of 2

Detection rules and the test workload

R1 · Tempo

One agent makes more than 20 calls in 10 seconds — faster than any human operator.

R2 · Probing

One agent is denied 3 times within 60 seconds — it keeps hitting permission walls.

R3 · Multi-tactic chain

One delegation grant touches 3+ sensitive ATT&CK tactics within 30 minutes.

  • Benign agents: CI tests, docs sync, ops inventory, nightly backup (looks like collection + exfiltration on purpose).
  • Misuse tree: contractor → orchestrator → five sub-agents, holding a staging-only “testing” grant.
  • Runs: 3 simulated hours × 50 seeds, baseline (shared key) vs NHI — identical IDS rules.

Results

Prevention by ATT&CK tactic

  • Credential access, lateral movement, collection and exfiltration: 0 calls allowed.
  • The ~31 calls per run that succeeded were discovery on staging — which the grant allowed.
  • So scoping limits damage, but detection is still needed.
  • Every refused delegation became evidence for the IDS.
Results · Digital forensics

Who, on whose behalf, did what, when

100% of misuse records traced to the contractor identity (baseline: 0%).

First alert: R2 probing, seconds after the first misuse call.

Tamper test: one edited record in a 634-record log detected at exactly record 100.

Discussion

What this means for GTG-1002

The attackers ran their agents on their own infrastructure, so victims cannot force scoped tokens on them. The controls apply in three places:

AI & tool platforms

Require a verified identity and an explicit, scoped grant before “security testing” use — a role-play claim becomes a named person’s decision.

Organisations running agents

Stop their own agents from being hijacked or over-trusted; every action stays attributable.

Target organisations

Issue short-lived, narrowly scoped machine credentials so harvested credentials are worth far less.

Limitations: synthetic data; hand-set thresholds; single signing key; no cross-organisation delegation; a slow attacker inside a legitimate scope is only detected, not blocked.

Conclusion

Identity is the missing control for agentic attacks

  • GTG-1002 used ordinary tools; the real failure was authority nobody had scoped and nobody could trace.
  • Per-agent identity + delegation that only narrows + identity-aware IDS + tamper-evident logs: 77% of misuse blocked, zero production exposure, zero false alerts, 100% attribution.
  • The same identity data that limits damage also sharpens detection and makes forensics possible.
